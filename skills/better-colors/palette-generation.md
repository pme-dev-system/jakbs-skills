# パレット生成

## スケールの規約

デザインシステムのパレットは、50(最も明るい)から950(最も暗い)までの数値スケールを使う。パレットサイズ別の標準ラベル:

| サイズ | ラベル |
| --- | --- |
| 5 | 100, 300, 500, 700, 900 |
| 9 | 50, 100, 200, 300, 500, 700, 800, 900, 950 |
| 11 | 50, 100, 200, 300, 400, 500, 600, 700, 800, 900, 950 |

11ステップはTailwindのデフォルトスケールに一致する。`400`/`600`の中間値が不要な場合は、より簡素なデフォルトとして9を使う。

## アルゴリズム

明度(L)、彩度パーセンテージ、色相(H)を持つベースカラーが与えられたとき:

**ステップ1. 明度の範囲:**

```
delta = 0.4
minL = max(0.05, baseL - delta)
maxL = min(0.95, baseL + delta)
```

明度は純粋な黒/白(彩度がゼロになる)を避けるため、[0.05, 0.95]にクランプされる。

**ステップ2. 明度を分配する。** maxL(最も明るい、ラベル50)からminL(最も暗い、ラベル950)まで均等に割り振る。

**ステップ3. ステップごとに彩度をクランプする。** 各明度レベルは、所与の色相と色空間に対して異なる最大彩度を持つ:

```
maxChroma = findMaxChroma(step[i].L, hue, colorSpace)
step[i].C = (chromaPercentage / 100) * maxChroma
```

これにより、すべてのステップが色域内に収まることが保証される。彩度の高いベースカラーは、最も明るい端と最も暗い端で彩度が低くなる。これは正しい、想定内の挙動である。

## CSS変数の出力

```css
:root {
  --color-50: oklch(0.971 0.012 250);
  --color-100: oklch(0.932 0.028 250);
  --color-200: oklch(0.882 0.048 250);
  --color-300: oklch(0.812 0.078 250);
  --color-500: oklch(0.623 0.188 250);
  --color-700: oklch(0.445 0.138 250);
  --color-800: oklch(0.362 0.108 250);
  --color-900: oklch(0.289 0.078 250);
  --color-950: oklch(0.215 0.048 250);
}
```

## 複数色相のパレット

複数の色相のパレットを生成する場合は、すべてで同じ**明度**と**彩度パーセンテージ**を使う。同じLは、知覚される明るさが等しくなることを保証する。同じ彩度パーセンテージ(絶対彩度ではない)は、各色相の最大値に対して等しい鮮やかさを保証する。

```css
:root {
  /* 同じL、同じC%(最大値の80%): 色相ごとに絶対Cは異なる */
  --blue-500: oklch(0.623 0.141 250);   /* 最大値0.176の80% */
  --green-500: oklch(0.623 0.157 145);  /* 最大値0.196の80% */
  --red-500: oklch(0.623 0.202 25);     /* 最大値0.253の80% */
}
```

異なる色相は、同じ明度でも異なる最大彩度を持つ。色相間で同じ絶対C値を使うと、一部の色が他よりも鮮やかに見えてしまう。

## ダークモード

まずライトとダークのセマンティックロールを入れ替え、その後ダークの見た目に合わせてマッピングされた値を調整する。

```css
:root {
  --color-bg: var(--color-50);
  --color-text: var(--color-950);
}

.dark {
  --color-bg: var(--color-950);
  --color-text: var(--color-50);
}
```

すべてのパレットステップを機械的に反転させない。ダークの見た目には、多くの場合異なる彩度と明度の間隔が必要であり、OKLCHのステップが均等であっても、すべての前景/背景ペアのコントラストが保たれる保証はない。各ペアを再チェックし、必要に応じてダークトークンを個別に調整する。

## なぜHSLパレットを使わないのか

**色相ドリフト:** `hsl(240, 80%, 20%)`と`hsl(240, 80%, 90%)`は、知覚的には同じ色相ではない。明るいバリアントは紫方向に約16°シフトする。OKLCHの色相は安定している。

**明るさの不整合:** `hsl(60, 100%, 50%)`(黄色)と`hsl(240, 100%, 50%)`(青)は、HSLの明度は同じだが、知覚される明るさは大きく異なる。
